───────────────────────────────────────────────────────────────────────────────
🎯 PROBLEM STATEMENT
───────────────────────────────────────────────────────────────────────────────

ISSUE: Jadwal ujian masih menampilkan status dari user sebelumnya saat siswa 
bergantian login di device yang sama.

SCENARIO:
  1. Siswa A login → Ujian SELESAI → Logout
  2. Siswa B login → Lihat jadwal → Status masih SELESAI (dari Siswa A) ❌

ROOT CAUSE:
  • Cache jadwal global (CBT_CACHE_JADWAL) tidak di-filter per-user
  • Status "SELESAI" dari user lain tertinggal di cache lokal
  • Flag _schedulesForUserId tidak konsisten saat login/logout
  • loadSchedules() ambil dari cache tanpa validasi user saat ini

IMPACT: HIGH
  • Siswa bingung dengan status ujian yang salah
  • Integritas data ujian terganggu
  • Pengalaman pengguna buruk di device shared

───────────────────────────────────────────────────────────────────────────────
✅ SOLUTION IMPLEMENTED
───────────────────────────────────────────────────────────────────────────────

3 KOMPONEN UTAMA:

1️⃣  CLEAR CACHE PER-USER SAAT LOGOUT (mobile-core.js)
   ─────────────────────────────────────────────────
   Location: nav-logout click handler
   
   Action:
   • Hapus CBT_CACHE_JADWAL_${userId}
   • Hapus CBT_CACHE_JADWAL_TIME_${userId}
   • Hapus CBT_${userId}_* (semua state exam)
   • Hapus CBT_SUBMITTED_*_${userId} (status submission)
   
   Result: Cache benar-benar bersih saat user logout
   
   Code Changes:
   - Added loop to iterate localStorage keys
   - Filter keys by userId pattern
   - Remove matching keys with logging
   - Total: ~20 lines added


2️⃣  FORCE-REFRESH JADWAL SAAT LOGIN (script.js)
   ──────────────────────────────────────────────
   Location: btnConfirmLogin click handler
   
   Action:
   • Clear CBT_CACHE_JADWAL_${userId} sebelum fetch
   • Fetch jadwal dari Supabase via getSchedules()
   • Set _schedulesForUserId flag untuk validasi
   • Status completion di-ambil dari server (bukan cache)
   
   Result: Jadwal selalu fresh dan sesuai user saat ini
   
   Code Changes:
   - Added cache clear before server fetch
   - Added logging untuk debugging
   - Total: ~10 lines added


3️⃣  ISOLASI CACHE PER-USER (script.js - syncAllDataForPortal)
   ──────────────────────────────────────────────────────────
   Location: syncAllDataForPortal() function
   
   Action:
   • Simpan cache jadwal global (untuk preview sebelum login)
   • Jika user sudah login, simpan cache per-user juga
   • Format: CBT_CACHE_JADWAL_${userId}
   
   Result: Cache terstruktur dan mudah di-manage per-user
   
   Code Changes:
   - Added per-user cache storage
   - Added logging untuk tracking
   - Total: ~8 lines added


4️⃣  RESTORE SESSION DENGAN FORCE-REFRESH (mobile-core.js)
   ──────────────────────────────────────────────────────
   Location: restoreLoginSession() IIFE
   
   Action:
   • Saat page refresh, clear cache jadwal user
   • Fetch jadwal terbaru dari server
   • Validasi status completion dari server
   
   Result: Session restore tidak membawa cache stale
   
   Code Changes:
   - Added cache clear before loadSchedules()
   - Added logging untuk debugging
   - Total: ~8 lines added

🔄 ALUR PERBAIKAN

SEBELUM FIX ❌
──────────────
Device A:
  Siswa A login
    → State.user = A
    → Load cache: CBT_CACHE_JADWAL (global)
    → Ujian SELESAI (status dari cache)
  
  Siswa A logout
    → State.user = null
    → Cache: CBT_CACHE_JADWAL masih ada ← TERTINGGAL
  
  Siswa B login
    → State.user = B
    → Load cache: CBT_CACHE_JADWAL (global)
    → Ujian SELESAI ← SALAH! (status dari Siswa A)


SESUDAH FIX ✅
──────────────
Device A:
  Siswa A login
    → State.user = A
    → Clear: CBT_CACHE_JADWAL_A
    → Fetch server: getSchedules(A)
    → Ujian SELESAI (status dari server untuk A)
  
  Siswa A logout
    → State.user = null
    → Clear: CBT_CACHE_JADWAL_A ← BERSIH
    → Clear: CBT_${A}_* ← BERSIH
    → Clear: CBT_SUBMITTED_*_A ← BERSIH
  
  Siswa B login
    → State.user = B
    → Clear: CBT_CACHE_JADWAL_B
    → Fetch server: getSchedules(B)
    → Ujian BELUM_MULAI ← BENAR! (status dari server untuk B)
